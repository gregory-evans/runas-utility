## 13.11.2026 — P0-исправления (кодировка, командная строка, парсинг флагов, ABI i386)

### Что исправлено

**1. Кодировка при элевации (`includes.pas`)**
При `{$H+}` строки — AnsiString в системной кодовой странице (CP_ACP), а не UTF-8.
`ShellExec` использовал `UTF8Decode()` перед вызовом `ShellExecuteExW`, что ломало
кириллические пути именно при повышении прав. Добавлена функция `AnsiToWide()` на
базе `MultiByteToWideChar(CP_ACP, ...)`; команда и параметры теперь конвертируются через неё.

**2. Экранирование команды в командной строке и MMF (`run.pas`)**
Путь команды с пробелами без кавычек ломал парсинг `CreateProcess(nil, lpCommandLine, ...)`.
Введена глобальная переменная `commandLine`, собираемая как
`Quoted(command) + ' ' + parameters`; она используется и для прямого запуска,
и для записи в MMF (элевация).

**3. Парсинг флагов обёртки (`run.pas`, `NormalStart`)**
Опции runas распознаются только при длине аргумента ровно 2 символа и начале с `-`.
Аргументы вида `--verbose`, `--elevated`, `-1` после команды больше не путаются с флагами
обёртки — они становятся параметрами целевой программы (с экранированием кавычками).
Неизвестный флаг до команды → `ERROR_UNDEFINED_PARAMETERS` (103); после команды → параметр.

**4. Новый код ошибки «нет команды» (`includes.pas`, `run.pas`)**
Добавлен `ERROR_NO_COMMAND = 116`: флаги переданы, но команда отсутствует
(ранее в этом случае код возврата был 101 — «нет параметров»).

**5. Явный `stdcall` для WinAPI (`includes.pas`)**
Без явной конвенции вызова 32-битная сборка (i386-Win32) падала Runtime error 216 на
`CreateProcessA`, `MultiByteToWideChar` и других внешних функциях. Всем внешним
объявлениям добавлен явный `stdcall`; исходный код из git (HEAD) под i386 тоже не работал —
ошибка была в проекте, а не только в новых вызовах.

**6. Тестовые сценарии (`tests/*.bat`)**
- Исправлена двойная кодировка кириллицы в рабочих копиях файлов (восстановлены из git).
- Найден и исправлен предсуществующий баг: `%TMPFILE` без закрывающего процента во внутренних
  командах `cmd.exe /c "..."` — переменная не разворачивалась, дочерний процесс писал в файл
  с буквальным именем (Test 2 в `test_parameters.bat`, Test 9 в `run_tests.bat`).
- Добавлен ограниченный цикл ожидания создания файла дочерним процессом (`ping -n 2` до 8 попыток) —
  обёртка завершается сразу после запуска, а холодный старт `cmd.exe` занимает секунды.
- Исправлены незакрытые скобки в `echo` внутри многострочных `if (...) else (...)` блоков
  (батч-парсер считал их за конец блока).
- Новый код 116 учтён в Test 7; добавлены регрессионные Test 11 (флаги цели) и
  Test 12 (команда из каталога с пробелом) в `test_parameters.bat`.
- Исправлена опечатка в итоговом отчёте `run_tests.bat` («Прошло» → «Падено»).

**7. Детект отказа UAC (`includes.pas`, `run.pas`)**
- В fMask `ShellExec` добавлен `SEE_MASK_NOCLOSEPROCESS`; если `hProcess = 0`, считаем неудачей (хендл закрывается после проверки).
- Новый код `ERROR_UAC_DENIED = 117` + сообщение `TXT_UAC_DENIED`: при неудаче ShellExecuteEx выходим сразу, не дожидаясь события.
- Тест 5 в `tests/test_elevation.bat`: запускается копия обёртки и переименовывается, чтобы ShellExecuteExW не нашёл файл; если сбой не воспроизвести в этом окружении — SKIP. Исправлен `%TMPFILE` в Test 3.
