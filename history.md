## 13.11.2026 — P0-исправления (кодировка, командная строка, парсинг флагов, ABI i386)

### Что исправлено
**1. Кодировка при элевации (`includes.pas`)**
При `{$H+}` строки — AnsiString в системной кодовой странице (CP_ACP), а не UTF-8.
`ShellExec` использовал `UTF8Decode()` перед вызовом `ShellExecuteExW`, что ломало
кириллические пути именно при повышении прав. Добавлена функция `AnsiToWide()` на
базе `MultiByteToWideChar(CP_ACP, ...)`; команда и параметры теперь конвертируются через неё.

**2. Экранирование команды в командной строке и MMF (`run.pas`)**
Путь команды с пробелами без кавычек ломал парсинг `CreateProcess(nil, lpCommandLine, ...)`.
Введена глобальная переменная `commandLine`, собираемая как
`Quoted(command) + ' ' + parameters`; она используется и для прямого запуска,
и для записи в MMF (элевация).

**3. Парсинг флагов обёртки (`run.pas`, `NormalStart`)**
Опции runas распознаются только при длине аргумента ровно 2 символа и начале с `-`.
Аргументы вида `--verbose`, `--elevated`, `-1` после команды больше не путаются с флагами
обёртки — они становятся параметрами целевой программы (с экранированием кавычками).
Неизвестный флаг до команды → `ERROR_UNDEFINED_PARAMETERS` (103); после команды → параметр.

**4. Новый код ошибки «нет команды» (`includes.pas`, `run.pas`)**
Добавлен `ERROR_NO_COMMAND = 116`: флаги переданы, но команда отсутствует
(ранее в этом случае код возврата был 101 — «нет параметров»).

**5. Явный `stdcall` для WinAPI (`includes.pas`)**
Без явной конвенции вызова 32-битная сборка (i386-Win32) падала Runtime error 216 на
`CreateProcessA`, `MultiByteToWideChar` и других внешних функциях. Всем внешним
объявлениям добавлен явный `stdcall`; исходный код из git (HEAD) под i386 тоже не работал —
ошибка была в проекте, а не только в новых вызовах.

**6. Тестовые сценарии (`tests/*.bat`)**
- Исправлена двойная кодировка кириллицы в рабочих копиях файлов (восстановлены из git).
- Найден и исправлен предсуществующий баг: `%TMPFILE` без закрывающего процента во внутренних
  командах `cmd.exe /c "..."` — переменная не разворачивалась, дочерний процесс писал в файл
  с буквальным именем (Test 2 в `test_parameters.bat`, Test 9 в `run_tests.bat`).
- Добавлен ограниченный цикл ожидания создания файла дочерним процессом (`ping -n 2` до 8 попыток) —
  обёртка завершается сразу после запуска, а холодный старт `cmd.exe` занимает секунды.
- Исправлены незакрытые скобки в `echo` внутри многострочных `if (...) else (...)` блоков
  (батч-парсер считал их за конец блока).
- Новый код 116 учтён в Test 7; добавлены регрессионные Test 11 (флаги цели) и
  Test 12 (команда из каталога с пробелом) в `test_parameters.bat`.
- Исправлена опечатка в итоговом отчёте `run_tests.bat` («Прошло» → «Падено»).

**7. Детект отказа UAC (`includes.pas`, `run.pas`)**
- В fMask `ShellExec` добавлен `SEE_MASK_NOCLOSEPROCESS`; если `hProcess = 0`, считаем неудачей (хендл закрывается после проверки).
- Новый код `ERROR_UAC_DENIED = 117` + сообщение `TXT_UAC_DENIED`: при неудаче ShellExecuteEx выходим сразу, не дожидаясь события.
- Тест 5 в `tests/test_elevation.bat`: запускается копия обёртки и переименовывается, чтобы ShellExecuteExW не нашёл файл; если сбой не воспроизвести в этом окружении — SKIP. Исправлен `%TMPFILE` в Test 3.

**8. Случайная компонента в именах MMF/Event (`run.pas`)**
- FPC не инициализирует генератор `Random` автоматически (проверено: два запуска дают одинаковое значение), поэтому при старте вызывается `Randomize`.
- Добавлена функция `UniqueSuffix()` — 8 hex-цифр из `Random(MaxInt)`. Имена MMF/Event теперь = префикс + PID + `_` + суффикс (один суффикс на оба имени).

**9. Устранение дублирования запуска команды (`run.pas`)**
- Общая процедура `RunTarget()` (запуск глобальной `commandLine`, при неудаче — `Halt(ERROR_CREATE_PROCESS)`); используется в `NormalStart`, `StartElevationProcess` и `ElevatedStart`.
- Попутно устранена несогласованность: элевированный дочерний процесс читал MMF в глобальную `command`, а остальные пути использовали `commandLine`; теперь все пути работают с одной переменной.

**10. Перегрузка `IntToStr(Value: DWORD)` (`includes.pas`)**
- Добавлена перегрузка с точным совпадением типа для `DWORD` (возврат `GetCurrentProcessId`). Реализация через `QWord` — беззнаковая семантика: значения > $7FFFFFFF не превращаются в отрицательные.

**11. Замена глобальных переменных структурой (`run.pas`)**
- Все поля состояния (`mode`, `elevation`, `command`, `parameters`, `commandLine`, `mmfName`, `mmfHandle`, `eventName`, `eventHandle`) собраны в структуру `TApp`; единственная глобальная переменная — `app`. Все хендлы инициализируются нулём (ранее `eventHandle` не инициализировался).
- Примечание: FPC 3.2.2 принимает в инициализаторе записи только точные имена полей через `;` (запятые — синтаксическая ошибка), отсюда форма `(mode: SW_NORMAL; elevation: False; ...)`.

**12. Проверка существования программы перед запуском (`includes.pas`, `run.pas`)**
- `GetProgramPart()` выделяет программу из командной строки (учитывая кавычки); `ProgramExists()` проверяет её существование; `RunTarget()` при отсутствии выводит `TXT_COMMAND_NOT_FOUND` и завершается с новым кодом `ERROR_COMMAND_NOT_FOUND = 118`.
- Голое имя без разделителей (`notepad`) не проверяется — его разрешит через PATH сам CreateProcess.
- Важное открытие: в kernel32 этой старой системы **нет экспорта `FileExistsA`** (проверено GetProcAddress), поэтому статический импорт роняет процесс ещё до main (код 0xC000013A). Функция разрешается лениво через `GetProcAddress`; если API недоступно — проверка пропускается и поведение не меняется.

**13. Удаление зависимости от unit sysutils (`run.pas`, `includes.pas`)**
- Из `uses` программы убран `sysutils`: в `includes.pas` перенесены только реально используемые функции — `Random(l: longint)`, `Randomize` (Mersenne Twister, алгоритм из FPC RTL sysutils), перегрузки `IntToStr(QWord/DWORD)` и `IntToHex(Longint; Digits)`. Неиспользуемые перегрузки (random(int64/extended), IntToHex(Int8..UInt64)) не переносились.
- Бинарник уменьшился вдвое: 97280 → 47104 байта.
- Исправлены недочёты при переносе: `mt_index` и `OldRandSeed` были объявлены как `const`, хотя присваиваются (FPC 3.2.2 это терпит, но нестандартно) — вынесены в `var`; хрупкий guard `{$ifdef FPC_HAS_FEATURE_RANDOM}` удалён (символ определён не во всех версиях FPC); `{$R-}{$Q-}` ограничены только блоком генератора; код приведён к стилю проекта (отступы, закрывающие комментарии `end; { Name() }`, единый регистр).

**14. Поддержка `CREATE_NO_WINDOW` — флаг `-w` (`includes.pas`, `run.pas`, tests)**
- `TApp.noWindow`; парсер принимает `-w`. `RunTarget()` передаёт в CreateProcess `CREATE_NO_WINDOW` вместо `CREATE_NEW_CONSOLE` при `-w` (консоль у цели не создаётся вовсе, в отличие от `-h` = SW_HIDE).
- Протокол элевации расширен: 5-й аргумент (`1`/`0`) передаёт флаг в элевированный процесс; `ElevatedStart()` читает его (отсутствует — False). При `-w -a` у элевированной копии обёртки дополнительно выставляется `SEE_MASK_NO_CONSOLE`.
- Справка обновлена (`TXT_HELP_2`); новый Тест 13 в test_parameters.bat.

**15. CI: GitHub Actions workflow (`.github/workflows/build.yml`)**
- Сборка на `windows-latest` при каждом push/PR: FPC ставится через Chocolatey (последняя стабильная версия — заодно страхует от регрессий на новых FPC, как с `FPC_HAS_FEATURE_RANDOM`), запускается `build.bat`, `run.exe` загружается артефактом.

**16. Кэш токена, длинные алиасы флагов, verbose-режим (`includes.pas`, `run.pas`, tests)**
- Кэш: результат `IsRunningAsAdmin()` хранится в unit-level переменных (аналогично `fileExPtr`); повторные вызовы не открывают токен заново.
- Длинные алиасы всех опций (`--normal`, `--minimize`, `--maximize`, `--hide`, `--nowindow`, `--verbose`, `--admin`, `--help`) распознаются только до команды; после команды аргументы с дефисом остаются параметрами цели (граница зафиксирована в README и покрыта Тестами 11/15).
- Verbose: флаг `-v` (`TApp.verbose`) + процедура `VLog()` выводит промежуточные шаги потока в stderr с префиксом `[run]`; справка обновлена. Новые Тесты 14–15.

**17. Ранний детект смерти элевированного дочернего (код 119) (`includes.pas`, `run.pas`, tests)**
- `ShellExec` теперь возвращает хендл запущенного процесса (out-параметр, вместо закрытия его сразу).
- Родитель ждёт `WaitForMultipleObjects(2, {event, hProcess}, 10s)`: событие → успех; смерть дочернего до сигнала → сразу код `ERROR_ELEVATED_CHILD_FAILED = 119` (+ VLog с кодом выхода дочернего); таймаут при живом дочернем — прежний код 109.
- Выявлена и обходится ошибка ABI FPC 3.2.2 (i386): external с open-array параметром передаёт аргументы некорректно (`WaitForMultipleObjects` возвращал WAIT_TIMEOUT мгновенно) — объявление через указатель на фиксированный массив `PWOHandleArray`, как в юните windows.
- Удалена неиспользуемая `Waiting()`; в README добавлены строки кодов 118 и 119 (118 отсутствовал в таблице), пункт 2 рекомендаций закрыт полностью. Новый Тест 6 в test_elevation.bat (регресс успеха нового ожидания).
- Проверено: scratch-сборка с несозданным MMF — элевированный дочерний умирал до сигнала, родитель выходил с кодом 119 за ~40 мс; production `-v -a cmd ...` → код 0, «event signaled», цель отработала с правами.
